# 用户验证记录模板

状态：尚未收集真实访谈或试用数据。下面是执行模板，不是用户反馈结果；本地自动化测试不能计作真实用户验证。

## 招募与记录

建议邀请创作者和愿意支持作品的读者，允许拒绝或中途退出。不要求受访者提供私钥、助记词或身份材料。访谈可以先使用本地演示，不强迫支付 Gas；记录必须注明使用本地链还是公共测试网、hub 地址与版本。未完成访谈前不要填写人数或正向结论。

每次记录：日期、匿名编号、角色、测试版本/网络、是否需要提示、任务成功/失败、实际用时（若确实计时）、原话及记录者。原话需经同意，避免保存与任务无关的个人信息。

## 任务

1. 不连接钱包，找到一个感兴趣的 Idea，说明它打算解决什么问题。
2. 如果你愿意支持两个作品，尝试找到支持篮并解释每份金额、总额与 Gas 的区别。旧版公共 hub 不含批量功能，不能将此任务标为公共批量成功。
3. 查看交易凭证，判断它属于本地链、RPC 估算还是实际公共交易；说明归档是否会删除链上内容。

## 访谈问题

- 最近一次分享或发现独立项目时，你使用了什么平台，遇到了什么实际障碍？
- 你通常如何表达支持？一次支持多个作者是否发生过？
- 你是否理解授权与支持是两笔不同交易？哪个环节最困惑？
- 如果仅为鼓励作品，你是否愿意承担页面展示的 Gas？为什么？
- 即使没有 BLITZ 奖励，你是否还会使用公开目录或收藏？缺少什么？

## 如何总结

分别记录观察、用户原话与团队推断。记录失败和负面反馈，不以测试币金额推断付费意愿，不把朋友礼貌评价当留存数据。用实际结果决定优先改入口、授权说明或产品方向；没有足够数据时保留“不确定”。
